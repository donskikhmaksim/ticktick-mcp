## 0. Предобработка / нормализация

Перед сравнением заголовков нормализуем:
1. lower-case; убрать префиксы-теги `[P0]/[P1]/[P2]/[SEO]/💳/🛡️/🪪/🗂/🚀/СЕЙЧАС ·/После сдачи ·/Выдача ·`.
2. срезать вводные-пустышки: `разобраться с…`, `изучить вопрос по…`, `решить вопрос с…`, `добиться ответа по…`, `проработать…`, `сделать…` — это НЕ содержательная часть, а «глагол-заполнитель».
3. транслитерация-мост: латиница↔кириллица одного термина считать одним токеном (`mountonsite`≈`майнтсайт`, `Workiz`, `Yelp`, `SSC`, `CSLB`).
4. вытащить «якоря сущностей»: номера заказов (`26AD18286`, `26AD22204`), суммы (`$10,079.72`, `23,782`, `$350`, `$25K`), формы (`Form 2553`, `1120-S`, `BQI`, `Part #434`), домены/сервисы (`fixroll.com`, `Mercury`, `Clopay`). Якорь = сильнейший сигнал тождества.

## 1. Роль КУРАТОР — семантическая группировка

Куратор группирует по **смыслу и объекту действия**, не по словам. Работает агрессивно (keep-both bias ВЫКЛючен): предлагает максимум слияний/групп, зная, что Максим — аппрувер и отбросит лишнее.

### 1.1 Что считаем СЕМАНТИЧЕСКИМ ДУБЛЕМ (кандидат на удаление одной из пары)
Дубль ⇔ **одно действие над одним объектом**, даже если слова разные. Признаки-триггеры:
- **Одинаковый якорь-сущность + одинаковый глагол-класс.** Пример: заказ `26AD18286` + глагол «оплатить инвойс» → две задачи (`6a5a57f8`, `6a5b3b97`) с **одинаковой суммой $10,079.72` = дубль.
- **Синонимы действия:** утвердить=одобрить=апрувнуть (approve); внести=занести=разнести (по фин.учёту); оформить=подать=получить (по лицензии). Совпал якорь + синоним-глагол → дубль.
- **Одинаковая сумма/номер = сильнейший дубль-сигнал.** `23,500+1.2%=23,782` и `500+1.2%=506` встречаются в ДВУХ задачах (`6a40db81`, `6a45e32a`) → дубль, даже при разных заголовках («Занести платёж Шевлякову» vs «Внести расход»).
- **Один и тот же курс/сервис под разным написанием:** `mountonsitetraining` ↔ `майнтсайт` → дубль.
- **Тройные дубли:** licensing fee $350 живёт в 3 задачах под 3 разными CSLB-зонтиками (`6a3c643a…782c`, `6a461587…e9c8`, `52ec77a2`) — та же сущность (ILF $350) → оставить 1.
- **Форвард-дубли из TG:** два TG-Inbox форварда из одного сообщения (одинаковый timestamp «24.07 05:42», одинаковый текст, один — без имени адресата) → дубль (`6a635e43`/`6a637a71`).

Правило вывода: в паре **оставляем карточку с бОльшим контентом / более свежую / с якорями (суммы, контакты, ссылки)**; удаляем «голую» переформулировку.

### 1.2 Что считаем UMBRELLA-ГРУППОЙ (родитель + шаги, НЕ удаление)
Umbrella ⇔ несколько задач — **этапы жизненного цикла одного объекта** (не одно действие, а разные). Триггеры:
- **Общий якорь-сущность + РАЗНЫЕ глаголы-этапы:** заказ `26AD18286`: заказать→одобрить→выбрать замену part→оплатить→отследить отправку→отследить доставку→получить welcome packet. Это ~10 задач одного заказа → одно дерево. (Самый яркий кейс: **один заказ размазан на ~10 карточек**.)
- **Один процесс/домен:** страхование (Commercial Auto + GL + WC + Bond + Inland Marine + агрегаты + оборудование + …) → зонтик «Страхование».
- **Существующий `parent` в TickTick** = готовая группа, не трогаем структуру, только реклассифицируем родителя («Задачи по сайту» — 13 подзадач; «Основная задача по лидогенерации» — 10).
- **Слияние ЗОНТИКОВ:** если про один объект есть 2–3 родителя (CSLB: `b0e0a33f` «план до выдачи» + `6a461586` «подать application» + `c0376766` «городские лицензии») → предложить один общий зонтик, дубли внутри снять.

### 1.3 Что считаем ШЛАКОМ / УСТАРЕВШИМ (кандидат на удаление)
- **Мусор-по-содержанию:** заголовок — ссылка на музыку/развлечение, не относящаяся к бизнесу (`6a15d7ab` Apple Music) → мусор.
- **Мета-задача, выполненная своими дочками:** «…**сделать задачи** для их оформления» (`69f8d73c`) — когда эти задачи уже созданы → устарела.
- **Самореферентные «собрать план/задачник»** (`6a3c0eee…ae40`, `6a4ef451…804c`) — цель была построить этот же task-лист; он построен → устарело.
- **Свершившийся факт:** «зарегистрировать компанию» (`69f4217f`), когда компания уже есть (EIN, S-Corp) → устарело.
- **Просроченная одноразовость:** due в прошлом + одноразовое действие («страт. сессия» due 05.06; «проверить удаление аккаунтов через 20 дней» due 23.07) → кандидат.
- **Признак давности:** `created` за 1.5–3 мес до сегодня + `due` в прошлом + пустой/односложный content — усиливает подозрение на шлак.

### 1.4 Что считаем КАНДИДАТОМ В SMART-ПЕРЕИМЕНОВАНИЕ
Заголовок «мутный», если он состоит преимущественно из глагола-заполнителя без объекта/цели: `Разобраться с…`, `Решить вопрос с…`, `HIS` (аббревиатура без расшифровки), `Условия для операторов`, `Local SEO задача`, `Внести расход`. Правило SMART: **глагол действия + конкретный объект + (зачем/дедлайн)**; объект/цель тянем из `content`.

### 1.5 Межпроектное (вынести, не удалять)
Задача НЕ про запуск гаражного бизнеса (личный/иной юр.спор: LinkedIn-претензия, иск BOA; другая компания Easy Peasy Inc) → предложить перенос в Personal/профильный проект. Сигнал: якорь-сущность чужой компании/личного дела, отсутствие связи с Fix&Roll в content.

## 2. Роль СКЕПТИК (адверсариальная проверка)

По КАЖДОМУ предложению Куратора Скептик пытается опровергнуть. Правила «НЕ дубль / НЕ шлак»:
- **Разные суммы ⇒ вероятно НЕ дубль, а этапы.** `$10,079.72` (котировка) vs `$11,261.38` (финал с tax+fuel) — не схлопывать, пометить ⚠, пусть человек сверит.
- **Разные объекты при одинаковом шаблоне ⇒ НЕ дубль, а группа.** «Переделать регистрацию **SSC** на админку» и «…**TickTick** на админку» — один паттерн, разные сервисы → группа, не дубль.
- **«Решить путь» vs «подать форму» ⇒ последовательные этапы, не дубль** (WC exemption: `5698f927` «решить путь» vs `6a3c643a…0ae6` «подать exemption») → ⚠.
- **«Внести» vs «разнести» ⇒ возможно разные бух.операции** (черновой ввод vs разноска по счетам) → ⚠, не удалять уверенно.
- **Общая задача-нянька поверх конкретных ⇒ спорно:** «Сделать созвон со страховщиками» при наличии конкретных quote-задач с тем же телефоном → предложить удаление ИЛИ превращение в зонтик, с ⚠.
- **Одноразовость с ценным вложением ⇒ проверить перед удалением** (PDF-roadmap, xlsx-выгрузка): не удалять, пока вложение не сохранено.

Итог Скептика: **уверенные** дубли/шлак (совпал якорь+сумма/точный текст) идут без пометки; **спорные** — с ⚠ и причиной, но остаются в списке (решает Максим). В эталоне: из ~26 удалений 9 помечены ⚠.

### 3.1 Правила разрешения конфликтов (когда подходит >1 колонки)
- **Платёж поставщику** (SSC-инвойс): по умолчанию 🚚 (держим в дереве заказа), НЕ 💰 — чтобы жизненный цикл заказа не рвался. (Альтернатива для Максима: чистые платежи → 💰.)
- **Гарантия:** на сайте/в договоре → 📣; ящик warranty@ / G Workspace → 🛠. (Кластер гарантии сшивается зонтиком G10 поверх колонок.)
- **Приём оплат от клиентов / Workiz Payments** → 💰 (деньги), хотя технически Workiz; настройка полей Workiz (estimate) → 🛠.
- **Аналитика сайта (GA4/call-tracking)** → 🛠, хотя живёт «на сайте».
- **Обучение** → 🚀 (операции), не 🪪, даже если про manufacturer-курсы дилера.
- **TG-форвард с ясной темой** (напр. «DocuSign LiftMaster») можно сразу класть в целевую колонку (🚚), а не держать в Inbox — агрессивный триаж. В эталоне из 12 TG-Inbox задач в 📥 оставлены только неоднозначные.

### 3.2 Диагностика «свалки»
Сигнал сломанной схемы: одна колонка держит >50% задач. Здесь **Legal = 132/209 (63%)** — это де-факто «прочее». Авто-инструмент должен флажить такую колонку и предлагать разнос. В эталоне Legal разошлась: Финансы 46, Лицензии 37, Закупки 20, IT 10, Операции 10, Маркетинг 4, Inbox 2, удалить 3.

### 3.3 Мисклассификации (эталонные примеры для проверки авто-инструмента)
Каждая — «сущность-якорь противоречит текущей колонке»:
- дилерство Clopay/Amarr/Nucor в **Legal** → 🚚 (поставщики);
- весь заказ SSC #26AD18286 в **Legal** → 🚚;
- страховые quote в **Legal** → 🪪;
- DMARC/MCP/домен в **Legal** → 🛠;
- обучение в **Legal** → 🚀;
- прайс-бук/Google-ссылка в **CRM & IT** → 🚚/🛠 (колонка CRM&IT упраздняется).

## 4. Как считались счётчики (для сверки авто vs эталон)

- **Дубль** = пара, где Куратор нашёл тождество (§1.1) и Скептик НЕ опроверг (или опроверг мягко → ⚠). Считаем ЧИСЛО удаляемых карточек (по 1 на пару/тройку). Эталон: 18 (+9 из них спорные ⚠ в отдельных категориях).
- **Шлак** = §1.3, число удаляемых. Эталон: 8.
- **Группа** = число предложенных umbrella-деревьев (родитель+≥2 шага), включая слияния зонтиков. Эталон: 14.
- **SMART** = число заголовков, подходящих под §1.4. Эталон: 29.
- **Реклассов** = число задач, у которых предлагаемая колонка ≠ «естественному наследнику» текущей (Mkt→📣 считается стабильным; Legal→любая, Delivery→🚀/🚚, CRM&IT→🛠, TG триаж = смена). Эталон: 173 из 205.
- **Межпроектных** = §1.5. Эталон: 3.

### Метрика сверки авто-инструмента с этим эталоном
1. **Дубли:** precision/recall по МНОЖЕСТВУ пар {оставить,удалить} (сверять по taskId; направление «кого оставить» — вторично).
2. **Группы:** для каждого эталонного зонтика — покрытие его членов авто-группой (Jaccard по taskId).
3. **Колонки:** accuracy предсказанной колонки по 205 задачам (матрица ошибок 7×7); отдельно — recall по 15 мисклассификациям из §3.3 как «золотым» точкам.
4. **SMART/шлак:** F1 по множеству taskId.

### Известные ловушки (чтобы авто-инструмент не ошибся)
- НЕ полагаться на `columnId` из `get_all_tasks`/`get_project_tasks` — его там нет; только `get_task_info`.
- Задачи БЕЗ `columnId` (в эталоне 3 шт: `6a645f7e`, `6a63b0e2…88a05`, `6a63b0e2…3eeb`) = «неразобранные», НЕ автоматически TG Inbox — классифицировать по содержанию.
- Разные суффиксы одного prefix-id (`6a3b0aa3…968b`/`968f`, `6a3c643a…0ae4/0ae5/0ae6`, `6a63b0e2…88a05/3eeb`) — это РАЗНЫЕ задачи, созданные одним батчем; не путать с одной.
- Суммы/номера — сильнее слов: сверять якоря до заголовков.
- «Completed: …» в activity у некоторых задач (напр. «Задачи по сайту», «Yelp», «GBP») при status Active — задача была закрыта и переоткрыта; не считать выполненной автоматически.
