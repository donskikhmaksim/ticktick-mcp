## Как считались 77 команд

Контрольная команда из задания: `rg -c "^@mcp\.tool\(" ticktick_mcp/src/server.py` → **77**.
(Без якоря `^` `rg -c "@mcp\.tool\("` даёт 85 — разница в 8 это
4 закомментированных декоратора отключённого `declutter` (`# @mcp.tool(...)`)
и 4 упоминания строки `@mcp.tool()` внутри чужого текста/докстрингов, не
являющиеся самим декоратором.) Список имён и номеров строк собран разбором
AST (`ast.walk` по `ticktick_mcp/src/server.py`, функции с декоратором
`mcp.tool` — то же, что реально видит `server.mcp.list_tools()` в
тест-повторителе).

## Четыре оси (дословно из ZAHOD1.md:883-886)

- **а.** Дословные примеры вывода сервера, которые модель должна воспроизвести
  обратно (заменители, строки плана, тексты отказов): обязаны совпадать с
  производящей функцией символ в символ.
- **б.** Имена команд внутри описаний — в первую очередь ссылки на
  `manual_triage` по имени (эта команда переименовывается в
  `apply_task_changes` во втором заходе; ссылающиеся на неё по имени описания
  нужно перечислить сейчас, чинить — не сейчас); заодно фиксируются любые
  другие упоминания имён команд по имени, включая ссылки на
  НЕСУЩЕСТВУЮЩИЕ имена.
- **в.** Перечни полей и допустимых значений против того, что реально
  принимает проверяющий код.
- **г.** Утверждения о поведении, которого больше нет.

Вердикт «Проверено, чисто.» — не пустота, а результат отдельной проверки по
коду (номера строк указаны там, где применимо). Там, где расхождение
найдено, ячейка начинается с маркера **⚠ РАСХОЖДЕНИЕ** и содержит устаревший
фрагмент дословно + номер строки в `server.py`, которому он противоречит.

Методология: каждая клетка с вердиктом «⚠ РАСХОЖДЕНИЕ» лично перепроверена
через прямое чтение `server.py` (`grep`/`sed`/`git show`) этим же исполнителем
— вслепую скопированных находок сторонних черновиков в таблице нет.
